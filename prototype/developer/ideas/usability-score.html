Usability score — developer onboarding

We compared the old basic setup flow (the fragmented Quickstart / API Testing / Configuration pages) against the new guided flow using the System Usability Scale (SUS) — a 10-item questionnaire scored 0–100. We used the all-positive SUS variant (Sauro & Lewis, 2011), which keeps the standard 10 items but phrases every one positively — easier to read and less error-prone to score, so higher is always better.

Result

SUS more than doubled — from a failing score to excellent.

Suggestions for improvement

Where the new flow still has room to grow.

01

Build confidence at the riskiest step

"Confident using it" rose but didn't top out — number registration still causes hesitation. Add inline validation, a progress indicator, and a clear success confirmation after each task.

02

Lighten the remaining heavy steps

"Cumbersome" and "complex" improved but aren't fully resolved — business verification and payment setup still feel like gates. Explore async/parallel verification so users aren't blocked.

03

Add a returning-user fast path

"Would use frequently" is naturally capped for a one-time setup. Offer a quick path for developers adding a second number or app, skipping steps they've done before.

04

Keep reducing upfront learning

"Lots to learn first" dropped sharply but persists for first-timers. Lead with the trial number and defer advanced concepts (webhooks, tokens) until they're needed.

Method: all-positive SUS (Sauro, J. & Lewis, J. R., 2011, "When designing usability questionnaires, does it hurt to be positive?", CHI). Scores are illustrative sample data.
