Broadcast Tool & Modular System

0→1 Product, Design System, WhatsApp Paid Messaging
Overview
Problems
Enterprises like Emirates, DHL, and Wells Fargo needed one tool to create and preview WhatsApp’s paid messages — but the template types kept growing and were owned by 4 different teams with no shared system.
Solutions
Designed a 0→1 broadcast tool and a modular card system (12 requirements → 7 cards) to discover and build 7 message templates — and scale to more.
My Role
  • Led as PM & designer with Eng across 4 teams
  • Defined the user flow, tool layout, and shared components
  • Wrote design guidelines for future scale
Impact

  • −75% build cost (4 → 1 team)
  • Scaled 7 → 10 template types
Context

The opportunity

WhatsApp paid messaging was growing fast — 3 categories and 7 templates, and counting. Enterprises like Emirates, DHL, and Wells Fargo needed one tool to create these paid messages and preview how they’d look.


The solution

One tool to discover and build 7 message templates.

Scope: 3 categories · 7 templates (growing) · 4 owner teams.  Design goals: learnability, consistency, scalability.

User Flow

Placement — extended on WhatsApp Manager

I defined placement first, so we could estimate the build effort, know which design system to leverage, and identify the dependencies to work with.


Mapped the end-to-end flow

From discovery, to configuration, to submission, and back to the broadcast management list. This defined the 3 pages to build.

Build the Tool

Page 1 — Message list

Leveraged existing patterns. Considerations: system consistency, build efficiency, and robust column control.


Page 2 — Category selection

New design for guiding and efficiency. Considerations: echo the design goals to help users discover offers, and prioritize efficiency over strict system consistency.

Modular System

Turned 12 requirements into 7 cards

Through working sessions with 4 teams, I gathered current and future needs, then defined a card system and its sequence.


Grouped by purpose, ordered by dependency

The cards fell into 3 core groups:

  • Template setting — Category + Overview, Name + Language
  • Format — Conditional Setup, Content, Buttons
  • Compliant — Agreement

A modular system on a two-column grid

Built on a two-column grid for progressive disclosure, scalability, and an easy-to-orient layout.


Components

A shared set of cards, each reusable across templates. Five building blocks make up every message:

Template name — name the template and set its language; the entry point shared by all templates.


Category — choose the message category (Marketing, Utility, Authentication) that defines the template’s purpose and rules.


Conditional setup — template-specific options that surface only when relevant, so the form stays focused.


Add media — attach a header image, video, or document, with inline preview.


Buttons — add interactive buttons — quick replies, links, or calls — up to the per-template limit.
